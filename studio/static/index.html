    A guided change review
    1. Describe the change. Try a sample, or add your source project. Include relevant downstream projects.
    2. Review the impact. Look at compatibility alerts and the systems suggested for review.
    3. Check the sources. Click a file button to see which source lines support a result.
    4. Plan and run tests. Review the existing tests and acceptance scenarios. Export the Jira brief for your team.
    What the labels mean
    Knowledge graph: a map of source components and their relationships.
    Owner declaration: a project owner supplied an interface or deployment mapping; it needs review.
    Unresolved: the tool could not establish a relationship. It does not mean there is no dependency.
    Source reference: a file and line range behind a result. Internal IDs and hashes are in technical details and exports.
    Needs review: analysis has finished; the change still needs human review and executed tests.
    AI advice unavailable: the AI reply could not be used. Source results remain available.
